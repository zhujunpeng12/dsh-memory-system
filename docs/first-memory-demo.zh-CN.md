# 第一次记忆：一条命令，看见写入、召回与纠错

在包含 `vault-guard/demo_memory.py` 的**新版源码目录**运行：

```sh
python vault-guard/demo_memory.py
```

需要 Python 3.10+，不需要 npm 安装、API Key、模型账号、数据库或运行中的 DSH。这里执行真实的项目 CLI，但数据全部是演示用的合成内容。若你的源码/已安装版本没有此文件，请先取得包含该演示的版本；已发布 npm `0.1.0` 不包含这个新增演示，源码版本号 `0.1.1` 也不代表已经发布到 npm。查验日期及 registry 来源见 [README 版本说明](../README.md#dsh-memory-system)。

## 这一遍会发生什么

1. 在新建的临时 Vault 里记录一条演示规则：“演示项目的发布检查使用蓝色清单。”它先是 **raw 原始事实**，不是自动晋升到 `rules.md` 的规则。
2. 启动新的 Python 进程召回。默认结果是 **0 条**，因为默认召回有意排除 raw，并非“没记住”。
3. 显式启用 raw 召回，找到蓝色清单。
4. 追加带 `supersedes` 的纠错：“演示项目的发布检查改为绿色清单。”
5. 再启动新进程，当前有效 raw 召回只返回绿色清单，旧结论不占据结果。
6. 切到历史审计，蓝色清单仍在，标为 `superseded`；绿色清单标为 `active`。
7. 验证原始字节没有被改写，删除整个临时演示目录。

脚本会核对这些结果，失败时非零退出，不会无条件打印成功。每次调用写入/召回 CLI 都使用新的子进程，并设有超时。

## 实际输出

输出由同一个脚本运行生成，保存为 [first-memory-demo-output.txt](first-memory-demo-output.txt)。回归测试会再次执行脚本并逐字核对，而不是维护一份手工编造的成功截图。随机 ID、临时路径和评分不展示，因此摘要可以复现。

其中最重要的两行是：

```text
5. 当前有效记忆：演示项目的发布检查改为绿色清单。（旧说法已排除）
6. 历史记录：已替代 = 演示项目的发布检查使用蓝色清单。
```

默认输出中文，可用 `--lang en` 查看英文步骤。机器可读结果：

```sh
python vault-guard/demo_memory.py --json
```

## 安全边界与没有证明的事

- 演示在 `TemporaryDirectory` 内调用真实 `vault-write.py ... --apply`，明确授权的是**刚创建的合成演示数据**。它覆盖子进程的 `MEMORY_VAULT`、`DSH_HOME`、session ID、home 和工作目录，不使用你已配置的个人 Vault。
- 这不代表正常写入可以跳过授权。真实 Vault 仍须先预览，再获用户明确同意后写入；宿主的 `memory_write` 确认机制不由此演示测试或绕过。
- 没有调用模型、启动 DSH、模拟聊天截图，也没有证明真实宿主中的自动注入、会话事件或 UI 权限流程。这里的“跨进程”是 Python 子进程间读取磁盘，不冒充实际 DSH 跨会话集成测试。
- 没有读取私有记忆、改动你的仓库配置或自动晋升规则。进程正常结束（包括抛出普通异常）时临时目录会被清理；强制杀进程/系统崩溃可能留下只含合成数据的临时目录。
- 只验证这条明确的词汇检索与纠错链，不是模型问答准确率、向量召回效果或大规模性能结论。
