# Your first memory: write, retrieve, correct, inspect history

From a **source checkout containing `vault-guard/demo_memory.py`**, run:

```sh
python vault-guard/demo_memory.py --lang en
```

Requires Python 3.10+. No npm install, API key, model account, database or running DSH is needed. The script uses the real project CLI with synthetic data. If your checkout or installed package lacks this file, obtain a revision that includes it; the published npm `0.1.0` package does not include this new demo. The source version `0.1.1` is not a verified npm release. See the dated [registry check in the README](../README.en.md#dsh-memory-system).

## What actually runs

1. A new temporary Vault records a synthetic rule: the demo project's release checks use a blue checklist. It is a **raw fact**, not an automatically promoted `rules.md` rule.
2. A fresh Python process runs default recall and gets **zero hits**, because raw evidence is excluded by default.
3. Explicit raw recall finds the blue-checklist fact.
4. A correction is appended with `supersedes`: use a green checklist instead.
5. Another fresh process retrieves only the effective green-checklist fact.
6. History mode retains blue as `superseded` and green as `active`.
7. The script verifies that the original raw bytes remain unchanged, then removes the temporary Vault.

Each write/recall call is a separate subprocess with a timeout. The script checks the actual results and exits nonzero if they disagree; it does not print success unconditionally.

## Reproducible output

[The output transcript](first-memory-demo-output.en.txt) was generated by this script, not hand-written or staged as a fake chat screenshot. A regression test reruns the script and compares the transcript exactly. The synthetic Chinese text deliberately exercises UTF-8 handling. Random IDs, temporary paths and ranking scores are omitted from the checked summary so it is repeatable.

Human-readable output defaults to Chinese; `--lang en` selects English step labels. The synthetic memory text remains Chinese. For language-independent machine-readable results:

```sh
python vault-guard/demo_memory.py --json
```

## Safety and limits

- Real `vault-write.py ... --apply` runs only against a newly created `TemporaryDirectory` Vault. This is authorization for **synthetic demo data**, not for your existing memories. Child-process `MEMORY_VAULT`, `DSH_HOME`, session ID, home and working directory are overridden.
- Normal writes to a real Vault still require preview and explicit user approval. This walkthrough neither tests nor bypasses the host's `memory_write` confirmation flow.
- No model API or live DSH host is involved. Fresh Python subprocesses demonstrate persistence on disk, not live DSH sessions, automatic injection, UI permissions or event wiring.
- The script never promotes a rule into your configured Vault or changes repository settings. Temporary data is removed on normal completion, including ordinary exceptions. A forced kill or system crash can leave a directory containing only synthetic data.
- The example verifies one explicit lexical retrieval/correction chain. It is not an answer-quality benchmark, semantic/vector search evaluation or a large-Vault performance claim.

Continue with [raw lifecycle design](raw-lifecycle-design.md) and the [transparent synthetic retrieval evaluation](recall-evaluation.md) before deciding how to use the system in a real DSH installation.
